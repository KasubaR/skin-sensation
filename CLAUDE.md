# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Run development server (uses SQLite automatically)
python manage.py runserver

# Apply migrations
python manage.py migrate

# After adding/changing models
python manage.py makemigrations

# Collect static files (required before deploying)
python manage.py collectstatic --noinput
```

## Architecture

### Django project layout
- `skinsensation/` — project config (settings, root urls, wsgi)
- `accounts/` — customer/staff auth (scaffold; routes under `/accounts/`)
- `services/` — bookable services domain logic (scaffold; API-style routes under `/catalog/`)
- `bookings/` — appointments (scaffold; routes under `/bookings/`)
- `payments/` — deposits and payments (scaffold; routes under `/payments/`)
- `notifications/` — confirmations and reminders (scaffold; routes under `/notifications/`)
- `dashboard/` — staff appointment management (scaffold; routes under `/dashboard/`)
- `core/` — public marketing site: home, services page, booking UI shell, gallery (`/` includes)
- `templates/` — all HTML templates (project-level, not app-level)
- `static/` — source static files served by Django in dev
- `staticfiles/` — generated by `collectstatic`, served on production

The public pages still use `core` views and flat URL names (`home`, `services`, `booking`, `gallery`). New apps use URL namespaces (e.g. `{% url 'bookings:...' %}` once routes exist).

### Template structure
Templates use Django inheritance. Every page extends `templates/layouts/base.html`, which:
- Loads `{% static 'index.css' %}` and `{% static 'index.js' %}` globally
- Includes `components/navbar.html` and `components/footer.html`
- Exposes blocks: `title`, `extra_css`, `content`, `extra_js`

Each page has its own CSS/JS pair in `static/`:
- `index.css` / `index.js` — home page
- `services.css` / `services.js` — services page
- `booking.css` / `booking.js` — booking page (multi-step flow)
- `gallery.css` — gallery page

Pages load their own CSS via `{% block extra_css %}` and JS via `{% block extra_js %}`.

### URLs and views
Root URL config: `skinsensation/urls.py` includes each app under a prefix, then `core` at `''`.

**Marketing (core)** — `core/urls.py`, `core/views.py`:
- `/` → `home` → `index.html`
- `/services/` → `services` → `services/index.html` (search/filter via query params + HTMX)
- `/booking/` → `booking` → `booking.html`
- `/gallery/` → `gallery` → `gallery.html`

Use `{% url 'name' %}` for core links (e.g. `{% url 'booking' %}`). Future booking APIs will live under the prefixed app includes above.

### Environment & database
`DJANGO_ENV` environment variable controls the environment:
- Unset (local dev): `DEBUG=True`, SQLite (`db.sqlite3`)
- `DJANGO_ENV=production` (cPanel): `DEBUG=False`, MySQL (`qualrijx_skin_sensation`)

### cPanel deployment
- Entry point: `app.py` (Passenger WSGI) — sets `DJANGO_ENV=production`
- App root on server: `public_html/skinsensationspa`
- Python version on server: 3.9.23
- Django version: 4.2 (constrained by Python 3.9)
- After pulling changes on server: run `python manage.py migrate` and `python manage.py collectstatic --noinput`, then restart the app in cPanel Setup Python App
- Production creates `cache/` and `logs/` automatically on startup; check `logs/django.log` if email or booking errors occur
- Appointment email reminders (cron in `Africa/Lusaka` timezone):
  - Day before: `python manage.py send_appointment_reminders` (e.g. daily at 08:00)
  - Same day: `python manage.py send_same_day_reminders` (e.g. daily at 07:00)
  - Use `--dry-run` on either command to preview targets without sending
- Set `NOTIFICATION_EMAIL_ENABLED=false` in env to disable outbound notification emails (staging)

### Staff dashboard (`dashboard` app)
- Mount: `/dashboard/` — requires `User.is_staff` (`@staff_required` in `dashboard/decorators.py`)
- **Overview** (`/dashboard/`) — KPI cards via `dashboard/stats.py`
- **Reports** (`/dashboard/reports/`) — Chart.js revenue/status/treatment charts
- **Appointments** — calendar, daily schedule, list, detail (status updates, staff reschedule, manual payment)
- **Payments** — list with status tabs (`?status=pending|verified|failed|refunded`); verify/reject on detail
- **Services / treatments** — CRUD under `/dashboard/services/`, `/dashboard/treatments/`
- **Customers** — list, detail, staff notes
- **Messages / reviews / business settings** — contact inbox, testimonial moderation, `BusinessInformation` edit
- **Activity log** — `StaffActivityLog` in `dashboard/models.py`; recent entries on overview
- **Promotions** — deferred (no `promotions` app; home page packages section is static HTML until requirements are defined)
- `accounts.models.Staff` = bookable therapist on calendar, **not** an admin role (admin access is `User.is_staff` only)

### Contact & communications (`communications` app)
- Public contact page: `/contact/` (form persists `ContactMessage`, emails managers via `send_contact_notification`)
- Success page: `/contact/success/`
- Site-wide phone/WhatsApp/maps come from `BusinessInformation` singleton (pk=1), exposed as `{{ business }}` via context processor
- Staff dashboard: `/dashboard/contact-messages/`, `/dashboard/business-settings/`
- After deploy: run `python manage.py migrate`; paste Google Maps embed URL in Business settings (Share → Embed a map → copy iframe `src`)
